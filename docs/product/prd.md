# 课程智能学习助手：产品需求与验收

## 用户问题与目标

目标用户是学习 AI 产品经理课程、准备转岗或求职的人。课程资料体量大、知识分散，用户既要理解 RAG/Agent 等概念，也要把知识转成学习计划、面试回答、PRD 和简历表达。

产品目标是用一个统一入口完成这些任务，并在回答后提供可检查的依据和反馈入口。展示版为单机应用：用户在本地网页操作，课程检索在本机执行，生成任务调用其自行配置的百炼 API。

## 核心流程

用户在学习助手输入内容。若选择功能标签，系统直接使用指定 Skill；未选择时由 Router 结合当前会话上下文判断意图。课程问答会进行保守 Query 改写，其余任务保留用户素材并检索相关知识。回答和执行记录关联保存到 SQLite，用户可查看来源、路由、耗时、错误及反馈。

| 场景 | 输入 | 可观察的结果 |
|---|---|---|
| 课程知识问答 | 概念问题或追问 | Top-K 检索、来源 ID、基于资料的回答与边界说明 |
| 学习路径 | 基础、目标、可用时间 | 符合时间约束的任务、课程建议与验收标准 |
| 面试题训练 | 主题或自己的回答 | 出题、考察点、点评、参考要点和追问，均在同一会话完成 |
| PRD 点评 | 粘贴需求文本 | 按优先级指出问题、修改建议和验收标准 |
| 简历优化 | 粘贴真实项目经历 | STAR 与面试表达；事实或结果缺失时明确待补充 |

## 关键约束

- 来源只能来自本次检索得到的片段；检索到相近主题不等于直接支持结论。
- 用户输入、简历、PRD 和课程文本均作为数据处理，不覆盖系统指令。
- 未配置 Key、模型超时、向量库异常时显示错误并写日志。
- 会话按 session_id 隔离；刷新后可继续同一会话。
- 无登录、支付、多租户、课程上传或线上部署。

## 验收要点

1. 问“RAG 是什么”能查看来源；追问“它和微调有什么区别”可补全指代。
2. `reg` 在课程语境下可以纠正为 RAG；无法确定的陌生词需要澄清。
3. “只有一天”的学习计划遵守一天约束。
4. 五个标签都能指定工作流；取消标签后恢复自动意图识别。
5. 面试问答在学习助手内进行，回答后可继续要求点评或追问。
6. 反馈能关联原问题、原回答及执行记录；模拟案例与真实反馈分别标注。
7. 看板统计技术执行情况，评测分别报告检索命中与需要人工判断的答案质量。

这些是功能验收标准，并非声称所有回答都正确。当前公开版的资料范围与历史结果见[数据范围](../data-scope.md)。
