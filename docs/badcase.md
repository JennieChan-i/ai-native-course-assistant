# Badcase 与反馈闭环

用户可在回答下点击“有问题”，选择类型并填写原因。系统将反馈关联到消息、会话、原问题和执行记录。处理人可保存原因分析、修复说明与复测记录；标记为“已解决”时要求填写修复与复测。SQLite 保存当前本机的真实操作记录，看板只统计这些记录。

“案例演示”中的六个案例是**模拟场景**，用于展示如何分析错别字、指代丢失、无依据回答、时间约束失效、路由错误和术语转写问题。每个案例列出模拟错误、根因、Prompt 调整、预期回答与回归标准。它们不自动计入反馈数量或修复通过率。

定位一个实际问题时，先比较原输入、路由意图和改写 Query，再检查检索候选、回答引用、模型状态与用户反馈。修复后在相同输入与数据版本上复测，并记录剩余不确定性。课程问答没有来源时要进一步检查资料是否真正覆盖该问题；PRD 和简历建议没有课程引用并不自动构成错误。
